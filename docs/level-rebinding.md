# Перепривязка заданий и готовых отверстий к уровням

Опция в окне «Обновить отметки» действует только на текущий запуск. Она не сохраняется в XML и не включает перепривязку в автоматическом апдейтере.

## Поведение

- «Автоматически»: только для заданий; для стен выбирается ближайший уровень снизу, для плит — ближайший по высоте.
- «К выбранному уровню»: доступно только в режиме «В выбранных элементах». Переключение на весь проект сбрасывает ручной режим и выбранный уровень.
- Ограничения режима показаны непосредственно в окне, без отдельного подтверждения при включении галочки.
- Без галочки болванка без уровня пропускается с подсказкой включить перепривязку. Отсутствующий обязательный параметр также даёт понятный пропуск; другие элементы продолжают обновляться.
- В результате перечисляются количества, причины и ID пропущенных элементов. Их можно выделить кнопкой отчёта.
- При отказе переноса параметра подробности показывают его GUID/встроенный идентификатор, ожидаемое и фактическое значения (числа Double — во внутренних единицах Revit). Для запрещённого зависимого элемента выводятся класс, категория, имя, семейство/тип, SuperComponent и Host. Краткие причины остаются сгруппированными отдельно от подробностей.
- Готовые отверстия и гильзы перепривязываются только в режиме «В выбранных элементах → К выбранному уровню». Если настоящий параметр уровня доступен для записи, используется изменение существующего экземпляра; иначе — пересоздание на той же основе. Автоматический и проектный режимы готовые отверстия не перепривязывают. Без галочки меняются только отметки и отдельно выбранное округление.

## Геометрия и уровни

Поддержаны свободные вертикальные семейства `OneLevelBased` категории «Обобщенные модели»: коды 111–116 и 121–124. При пустом коде распознаются четыре стандартных имени `Пересечение_Стена/Плита_Прямоугольное/Круглое`. Несовместимые сочетания имени и кода не перепривязываются.

Источник положения — `LocationPoint.Point`, а не общие отчётные параметры. Для прямоугольной стены это низ, для круглой — центр. У плиты опорная высота равна Z точки вставки минус 50 мм, согласно геометрии штатных создателей.

Подбор использует `Level.ProjectElevation`, независимо от базы отображаемых отметок. Несколько одинаково подходящих уровней считаются неоднозначностью. Если для стены нет уровня снизу, элемент пропускается. Эти случаи разрешаются явным выбором уровня.

У экземпляра, созданного скриптом без уровня, прежнее смещение не используется. После назначения уровня новое встроенное смещение вычисляется как `savedPoint.Z - target.ProjectElevation`. Поправка 50 мм не вычитается повторно из встроенного смещения.

Для изменения положения используется доступный для записи `INSTANCE_ELEVATION_PARAM`; для плиты допускается совместимый `INSTANCE_FREE_HOST_OFFSET_PARAM`. Проверяется связь параметра с реальной Z. У экземпляра без уровня доступность смещения проверяется после назначения уровня и регенерации. Если параметр нельзя изменить, экземпляр откатывается с причиной.

Прежняя формула отчётных параметров сохранена: высота базового уровня берётся из `Level.Elevation`, а смещение плиты — из `INSTANCE_FREE_HOST_OFFSET_PARAM - 50 мм`.

### Готовые отверстия

Для готовых отверстий используется отдельный путь. Поддержаны стандартные `Отверстие_Стена/Плита_Прямоугольное/Круглое`, `Гильза_Стена/Плита`, коды 126 и 221–224, а также четыре семейства WEANDREVIT 231/232, используемые «Вырезать». Уровень всегда выбирает пользователь; положение готового отверстия при перепривязке сохраняется, округление к нему не применяется.

Изменяется `FAMILY_LEVEL_PARAM`, а результат подтверждается по `FamilyInstance.LevelId`. Параметр «Уровень спецификации» не подменяет реальный уровень. Основа должна соответствовать профилю: стена или перекрытие. `INSTANCE_ELEVATION_PARAM` компенсируется до регенерации только при подтверждённой зависимости от уровня. Если такого смещения нет, смена уровня допустима лишь когда Revit сам сохраняет положение. Смещение от основы `INSTANCE_FREE_HOST_OFFSET_PARAM` для готового отверстия не используется как смещение от уровня.

Параметры отчёта готовой стены берутся из проверенного смещения от её уровня. Для плиты: `уровеньОсновы.ProjectElevation + смещениеПлиты - уровеньОтверстия.ProjectElevation`. Поэтому при разных уровнях основы и отверстия их абсолютная отчётная отметка остаётся согласованной. У WEANDREVIT высота базового уровня обновляется, если такой параметр существует. Та же формула плиты исправлена в автоматическом апдейтере RibbonCITRUS; при установке нужно обновить оба модуля.

## Защита изменений

Проверяются точка вставки, полный transform, параметры ширины, высоты, толщины и диаметра экземпляра и типа, тип и `GH_GUID` — до завершения транзакции и после неё. Общий `BoundingBox` не сравнивается: линии видимости и другие вспомогательные элементы могут менять его при смене уровня без изменения самого задания. Непредусмотренное изменение проверяемых данных откатывает элемент. Отдельно включённое округление заданий выполняется после проверки перепривязки и может менять их положение.

При пересоздании готового отверстия его Revit `ElementId` и `UniqueId` меняются, а `GH_GUID` сохраняется. Марки и размеры на чертежах не переносятся и не препятствуют пересозданию — это согласованное ограничение. Размерные параметры, положение, ориентация, основа/вырез, рабочий набор, фазы, закрепление и служебные связи CITRUS проходят обязательную проверку. Исходный экземпляр возвращается при откате неудачной замены; посторонние модельные элементы не должны удаляться вместе с ним.

Закрепление выбранного готового отверстия не препятствует прямой смене доступного для записи уровня: оно снимается внутри транзакции и восстанавливается перед проверкой и сохранением. При отказе исходное закрепление восстанавливается вместе с остальным состоянием. Для болванок правило не изменено.

При перепривязке выбранного готового отверстия отчётные параметры высоты базового уровня и смещения обновляются по возможности, отдельно от изменения размещения. При смене уровня смещение закономерно меняется: сравнение с прежним отчётным значением не требуется. Отсутствие отчётного параметра, неверный тип, отказ записи или пересчёт семейством после регенерации/commit не отменяют корректную перепривязку; причина и доступные ожидаемое/фактическое значения в миллиметрах попадают в подробности. Оба поля обрабатываются независимо. Положение не меняется ради совпадения отчётных данных. Фактические координаты, размеры, GUID, выбранный уровень, основа и отношения вырезания по-прежнему проверяются после обновления отчёта и после commit. Отдельное обновление отметок без перепривязки и обработка болванок сохраняют прежнюю строгую проверку отчёта.

Остальные заполненные пользовательские параметры переносятся по возможности. Если параметр отсутствует, доступен только для чтения, не принимает запись, не читается у исходного экземпляра или пересчитывается семейством, это не отменяет геометрически корректное пересоздание: замечание попадает только в подробности успешной операции. Ошибка чтения обязательного размерного параметра или `GH_GUID` и фатальная ошибка регенерации не подавляются. Пустые/пробельные строки и незаданные дополнительные параметры не затирают значения нового семейства. Например, автозаполнение `ADSK_Группирование` из пустой строки значением `4.Другие элементы систем` не является ошибкой перепривязки. Число `0` считается заполненным значением. `GH_GUID` и действующие идентификаторы Hub не относятся к необязательным описаниям: их отдельные проверки сохраняются.

Значения перенесённых параметров проверяются после записи всего набора, восстановления размещения и регенерации, затем повторно после commit. Немедленная проверка `AsDouble` после каждого `Set` могла отклонить промежуточное значение до пересчёта связанных параметров семейства. Контроль итоговых размеров и откат при реальном расхождении сохраняются. Это исправление покрыто тестом отложенного пересчёта на границе API; его результат на пользовательском RFA/RVT ещё нужно проверить в Revit.

Собственные вложенные компоненты пока не считаются автоматически безопасными для удаления: повторное создание родителя не гарантирует переноса проектных параметров и служебных данных каждого ребёнка. Помимо аннотаций, допускается узкое исключение для уже полученного через `GetDependentElements` зависимого объекта точного класса `Element`: без имени, категории, размещения, типа, Extensible Storage, закрепления, группы и принадлежности виду. Количество, значения и доступность его обычных параметров не блокируют пересоздание: они не определяют наличие модельной геометрии. Это эвристика для непрозрачных записей Revit, а не установленный классификатор их назначения; параметры такой удаляемой записи не переносятся. Объекты других классов и объекты с перечисленными признаками по-прежнему защищены. Полный результат `Document.Delete` сверяется с заранее разрешёнными ID; неожиданная каскадная потеря откатывает операцию. Проверки размеров, положения, `GH_GUID`, основы и вырезов самого отверстия сохраняются. Близкие номера ElementId сами по себе ничего не разрешают.

Если у отверстия есть служебные данные Cutter/Hub, для их переноса используется совместимая версия GloryHoleCutter. Контрольная подпись отверстия пересчитывается после смены уровня, только если исходное отверстие соответствовало сохранённой подписи; прежние ручные изменения не скрываются. Новая подпись `geometry-v1` исключает оба отчётных поля и сохраняет контроль идентичности, размеров и размещения. Старые полные подписи читаются совместимо. Изменение отчётного поля семейством после commit больше не вызывает косвенный откат через подпись Cutter. Для этого исправления необходимо обновить обе DLL: RefreshElevations и Cutter.

Для Hub переход со старого идентификатора результата на новый сохраняется в модели вместе с заменой, а файловая очередь и отправка запускаются только после успешного завершения операции. Прежняя очередь и авторство её событий не переписываются. Отверстия без этих данных не требуют загрузки Cutter. Отсутствующий или пустой Hub-параметр, пробелы, пустой GUID проекта и неположительные числовые ID означают отсутствие связи; отличия между такими пустыми представлениями не блокируют замену и не требуют записи. Появление действующего идентификатора вместо отсутствовавшей связи, повреждение заполненного идентификатора и изменение `GH_GUID` по-прежнему проверяются. Отсутствие настройки Hub не добавляет сетевых ожиданий.

Неизвестные схемы Extensible Storage препятствуют только пересозданию, при котором исходный экземпляр удаляется. При прямой смене уровня они остаются на том же экземпляре и не вызывают загрузку Cutter; проверяются неизменный UniqueId и наличие этих схем. Содержимое неизвестных схем команда не читает и не переписывает. Если одновременно присутствуют известные данные Cutter/Hub, их перенос и обновление контрольной подписи сохраняются.

У готовых отверстий дополнительно проверяются встроенные размеры, включая CASEWORK_WIDTH/HEIGHT у WEANDREVIT в плитах, основа и её грань, уровень/смещение основы, состояние закрепления, членство во вставках основы, полный набор соединений и их направление, полный набор вырезаемых незакреплёнными пустотами элементов. Отсутствие такой void-связи не считается ошибкой у нативного оконного выреза. Это проверки отношений Revit, а не измерение формы выреза в геометрическом ядре.

Групповые, вложенные, закреплённые, наклонённые и размещённые на основе болванки не перепривязываются автоматически. Для них выводится причина. Обычный путь обновления сохраняет штатную обработку предупреждений Revit. У готовых отверстий сообщение уровня Warning само по себе не отменяет смену уровня: используется штатная обработка Revit, а текст добавляется в подробности успешного результата. После commit повторно проверяются размеры, положение, идентичность, основа и отношения вырезания; их изменение откатывает отверстие даже при одном Warning. Error, повреждение документа и ошибка регенерации не допускаются. Строгая обработка предупреждений при перепривязке болванок не изменена.

Весь запуск объединён в один Undo. Ошибки отдельных элементов изолированы. Ошибка регенерации прерывает всю операцию. Апдейтер GloryHole временно приостанавливается на все транзакции и возвращается в прежнее состояние. Ошибка его восстановления выводится отдельно от результата сохранения модели.

## Автоматическая проверка

```powershell
dotnet test .\GloryHoleRefreshElevations.Tests\GloryHoleRefreshElevations.Tests.csproj
dotnet build .\GloryHoleRefreshElevations\GloryHoleRefreshElevations.csproj -c R2023
```

Тесты расчётов, жизненного цикла апдейтера и самого сервиса перепривязки работают без установленного Revit. Тесты сервиса используют ограниченные doubles на границе Revit API: моделируют параметры, commit, rollback и отказы; они не заменяют проверку геометрического ядра и реальных RFA/RVT.

Для пересоздания на 2026-10-13 прошли 262 теста этого модуля, 319 основных тестов Cutter и 5 тестов его моста метаданных. Обе DLL собраны для R2019–R2027, без PDB. Обновить нужно оба модуля. Дополнительная зависимость Newtonsoft.Json у RefreshElevations не появилась; она поставляется с Cutter. Реальный Revit и пользовательская модель не запускались.

Исправление ранней проверки высоты и диагностики зависимостей прошло 267/267 тестов RefreshElevations. Повторный пользовательский отчёт выявил избыточный контроль `ADSK_Группирование` и четыре безымянных объекта класса `Element` без категории. Для обновлённой политики переноса дополнительных параметров и обработки пустых зависимостей прошли 297/297 тестов. Все девять сборок R2019–R2027 собраны без ошибок и без PDB; настройки сохранены. Проверены автозаполнение группирования, непринятые дополнительные параметры, сохранение обязательных размеров/идентификаторов, продолжение при разрешённой пустой зависимости и откат неожиданного каскада. Проверка на пользовательской RFA/RVT всё ещё требуется; назначение четырёх объектов и остальные их свойства по снимку не установлены.

Отчёт от 2026-10-14 показал общий зависимый объект `Element` ID 2446714 с семью параметрами, без остальных перечисленных признаков. Проверка отсутствия параметров ошибочно блокировала все 22 отверстия и удалена. Регрессии покрывают один и 22 экземпляра с общей параметризованной зависимостью, обычные/shared параметры, а также восстановление исходного отверстия и зависимости при повреждении обязательных размеров, положения, `GH_GUID` или выреза. Прошли 304/304 теста и девять сборок R2019–R2027; PDB не создавались, хеши девяти файлов настроек/config не изменились. API doubles не устанавливают назначение реального объекта 2446714 и не заменяют повторный запуск на пользовательской модели.

Повторная проверка 2026-10-14 выявила четыре независимых лишних ограничения: любой Warning, неизвестный ES при сохранении исходного экземпляра, закрепление отверстия с записываемым уровнем и уже правильные вычисляемые отчётные параметры. После исправлений проходят 320/320 тестов. Проверены успешные сценарии и откат при повреждении размеров, положения, GH_GUID и выреза после commit с Warning, неверных readonly-отметках, потере неизвестной схемы и попытке перенести её на другой экземпляр. Это проверки границы API; форма реального выреза требует проверки в Revit.

На 2026-10-05 WPF проверен отдельным STA-приложением с настоящими XAML и CitrusTheme: 38 проверок, включая окна предупреждений, переключение режимов, запись чисел, отсутствие новых флагов в XML, клавишу Space и прокрутку при ограниченной высоте. Проверена отрисовка при 100% и 150%.

Матрица сборок — R2019–R2027. Для R2026 закреплён API 2026.0.0 (.NET 8), для R2027 — API 2027.0.0 (.NET 10). Бинарная DLL в корне репозитория предназначена для Revit 2023.

## Проверка в Revit перед использованием на рабочей модели

1. На копии модели создать штатные болванки стен и плит без уровня тем же скриптом замены. Без перепривязки проверить понятный пропуск и успешную обработку соседних корректных элементов.
2. Включить автоматическую перепривязку и выключить оба округления. Сравнить положение, ориентацию, размеры, уровень, смещение и `GH_GUID` до и после для прямоугольных и круглых профилей.
3. Проверить скопированные между этажами болванки с существующей привязкой, а также модель с изменённой базой отображения отметок.
4. Для выбранных элементов указать уровень выше болванки: отрицательное смещение допустимо, геометрия должна сохраниться. У всего проекта ручной режим должен быть недоступен.
5. Проверить одинаковые уровни, равные расстояния до уровней плит, отсутствие нижнего уровня стен, группы, вложенные/закреплённые/наклонённые экземпляры и параметры только для чтения.
