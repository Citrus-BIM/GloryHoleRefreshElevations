# Перепривязка заданий и готовых отверстий к уровням

Опция в окне «Обновить отметки» действует только на текущий запуск. Она не сохраняется в XML и не включает перепривязку в автоматическом апдейтере.

## Поведение

- «Автоматически»: только для заданий; для стен выбирается ближайший уровень снизу, для плит — ближайший по высоте.
- «К выбранному уровню»: доступно только в режиме «В выбранных элементах». Переключение на весь проект сбрасывает ручной режим и выбранный уровень.
- Ограничения режима показаны непосредственно в окне, без отдельного подтверждения при включении галочки.
- Без галочки болванка без уровня пропускается с подсказкой включить перепривязку. Отсутствующий обязательный параметр также даёт понятный пропуск; другие элементы продолжают обновляться.
- В результате перечисляются количества, причины и ID пропущенных элементов. Их можно выделить кнопкой отчёта.
- Готовые отверстия и гильзы перепривязываются только в режиме «В выбранных элементах → К выбранному уровню». Если настоящий параметр уровня доступен для записи, используется изменение существующего экземпляра; иначе — пересоздание на той же основе. Автоматический и проектный режимы готовые отверстия не перепривязывают. Без галочки меняются только отметки и отдельно выбранное округление.

## Геометрия и уровни

Поддержаны свободные вертикальные семейства `OneLevelBased` категории «Обобщенные модели»: коды 111–116 и 121–124. При пустом коде распознаются четыре стандартных имени `Пересечение_Стена/Плита_Прямоугольное/Круглое`. Несовместимые сочетания имени и кода не перепривязываются.

Источник положения — `LocationPoint.Point`, а не общие отчётные параметры. Для прямоугольной стены это низ, для круглой — центр. У плиты опорная высота равна Z точки вставки минус 50 мм, согласно геометрии штатных создателей.

Подбор использует `Level.ProjectElevation`, независимо от базы отображаемых отметок. Несколько одинаково подходящих уровней считаются неоднозначностью. Если для стены нет уровня снизу, элемент пропускается. Эти случаи разрешаются явным выбором уровня.

У экземпляра, созданного скриптом без уровня, прежнее смещение не используется. После назначения уровня новое встроенное смещение вычисляется как `savedPoint.Z - target.ProjectElevation`. Поправка 50 мм не вычитается повторно из встроенного смещения.

Для изменения положения используется доступный для записи `INSTANCE_ELEVATION_PARAM`; для плиты допускается совместимый `INSTANCE_FREE_HOST_OFFSET_PARAM`. Проверяется связь параметра с реальной Z. У экземпляра без уровня доступность смещения проверяется после назначения уровня и регенерации. Если параметр нельзя изменить, экземпляр откатывается с причиной.

Прежняя формула отчётных параметров сохранена: высота базового уровня берётся из `Level.Elevation`, а смещение плиты — из `INSTANCE_FREE_HOST_OFFSET_PARAM - 50 мм`.

### Готовые отверстия

Для готовых отверстий используется отдельный путь. Поддержаны стандартные `Отверстие_Стена/Плита_Прямоугольное/Круглое`, `Гильза_Стена/Плита`, коды 126 и 221–224, а также четыре семейства WEANDREVIT 231/232, используемые «Вырезать». Уровень всегда выбирает пользователь; положение готового отверстия при перепривязке сохраняется, округление к нему не применяется.

Изменяется `FAMILY_LEVEL_PARAM`, а результат подтверждается по `FamilyInstance.LevelId`. Параметр «Уровень спецификации» не подменяет реальный уровень. Основа должна соответствовать профилю: стена или перекрытие. `INSTANCE_ELEVATION_PARAM` компенсируется до регенерации только при подтверждённой зависимости от уровня. Если такого смещения нет, смена уровня допустима лишь когда Revit сам сохраняет положение. Смещение от основы `INSTANCE_FREE_HOST_OFFSET_PARAM` для готового отверстия не используется как смещение от уровня.

Параметры отчёта готовой стены берутся из проверенного смещения от её уровня. Для плиты: `уровеньОсновы.ProjectElevation + смещениеПлиты - уровеньОтверстия.ProjectElevation`. Поэтому при разных уровнях основы и отверстия их абсолютная отчётная отметка остаётся согласованной. У WEANDREVIT высота базового уровня обновляется, если такой параметр существует. Та же формула плиты исправлена в автоматическом апдейтере RibbonCITRUS; при установке нужно обновить оба модуля.

## Защита изменений

Проверяются точка вставки, полный transform, параметры ширины, высоты, толщины и диаметра экземпляра и типа, тип и `GH_GUID` — до завершения транзакции и после неё. Общий `BoundingBox` не сравнивается: линии видимости и другие вспомогательные элементы могут менять его при смене уровня без изменения самого задания. Непредусмотренное изменение проверяемых данных откатывает элемент. Отдельно включённое округление заданий выполняется после проверки перепривязки и может менять их положение.

При пересоздании готового отверстия его Revit `ElementId` и `UniqueId` меняются, а `GH_GUID` сохраняется. Марки и размеры на чертежах не переносятся и не препятствуют пересозданию — это согласованное ограничение. Пользовательские параметры, рабочий набор, фазы, закрепление и служебные связи CITRUS должны сохраниться. Исходный экземпляр возвращается при откате неудачной замены; другие модельные элементы не должны удаляться вместе с ним.

Если у отверстия есть служебные данные Cutter/Hub, для их переноса используется совместимая версия GloryHoleCutter. Контрольная подпись отверстия пересчитывается после смены уровня, только если исходное отверстие соответствовало сохранённой подписи; прежние ручные изменения не скрываются. Для Hub переход со старого идентификатора результата на новый сохраняется в модели вместе с заменой, а файловая очередь и отправка запускаются только после успешного завершения операции. Прежняя очередь и авторство её событий не переписываются. Отверстия без этих данных не требуют загрузки Cutter. Пустой GUID, пробелы и нулевые значения Hub-параметров не считаются подключением. Отсутствие настройки Hub не добавляет сетевых ожиданий.

У готовых отверстий дополнительно проверяются встроенные размеры, включая CASEWORK_WIDTH/HEIGHT у WEANDREVIT в плитах, основа и её грань, уровень/смещение основы, состояние закрепления, членство во вставках основы, полный набор соединений и их направление, полный набор вырезаемых незакреплёнными пустотами элементов. Отсутствие такой void-связи не считается ошибкой у нативного оконного выреза. Это проверки отношений Revit, а не измерение формы выреза в геометрическом ядре.

Групповые, вложенные, закреплённые, наклонённые и размещённые на основе болванки не перепривязываются автоматически. Для них выводится причина. Обычный путь обновления сохраняет штатную обработку предупреждений Revit; перепривязка отменяется при предупреждениях, чтобы Revit не исправлял геометрию неявно.

Весь запуск объединён в один Undo. Ошибки отдельных элементов изолированы. Ошибка регенерации прерывает всю операцию. Апдейтер GloryHole временно приостанавливается на все транзакции и возвращается в прежнее состояние. Ошибка его восстановления выводится отдельно от результата сохранения модели.

## Автоматическая проверка

```powershell
dotnet test .\GloryHoleRefreshElevations.Tests\GloryHoleRefreshElevations.Tests.csproj
dotnet build .\GloryHoleRefreshElevations\GloryHoleRefreshElevations.csproj -c R2023
```

Тесты расчётов, жизненного цикла апдейтера и самого сервиса перепривязки работают без установленного Revit. Тесты сервиса используют ограниченные doubles на границе Revit API: моделируют параметры, commit, rollback и отказы; они не заменяют проверку геометрического ядра и реальных RFA/RVT.

Для пересоздания на 2026-10-13 прошли 262 теста этого модуля, 319 основных тестов Cutter и 5 тестов его моста метаданных. Обе DLL собраны для R2019–R2027, без PDB. Обновить нужно оба модуля. Дополнительная зависимость Newtonsoft.Json у RefreshElevations не появилась; она поставляется с Cutter. Реальный Revit и пользовательская модель не запускались.

На 2026-10-05 WPF проверен отдельным STA-приложением с настоящими XAML и CitrusTheme: 38 проверок, включая окна предупреждений, переключение режимов, запись чисел, отсутствие новых флагов в XML, клавишу Space и прокрутку при ограниченной высоте. Проверена отрисовка при 100% и 150%.

Матрица сборок — R2019–R2027. Для R2026 закреплён API 2026.0.0 (.NET 8), для R2027 — API 2027.0.0 (.NET 10). Бинарная DLL в корне репозитория предназначена для Revit 2023.

## Проверка в Revit перед использованием на рабочей модели

1. На копии модели создать штатные болванки стен и плит без уровня тем же скриптом замены. Без перепривязки проверить понятный пропуск и успешную обработку соседних корректных элементов.
2. Включить автоматическую перепривязку и выключить оба округления. Сравнить положение, ориентацию, размеры, уровень, смещение и `GH_GUID` до и после для прямоугольных и круглых профилей.
3. Проверить скопированные между этажами болванки с существующей привязкой, а также модель с изменённой базой отображения отметок.
4. Для выбранных элементов указать уровень выше болванки: отрицательное смещение допустимо, геометрия должна сохраниться. У всего проекта ручной режим должен быть недоступен.
5. Проверить одинаковые уровни, равные расстояния до уровней плит, отсутствие нижнего уровня стен, группы, вложенные/закреплённые/наклонённые экземпляры и параметры только для чтения.
6. Повторить с включённым и выключенным апдейтером, с округлением и без него. Проверить сохранение состояния апдейтера и единую команду Undo.
7. Перепривязать незакреплённое задание с включёнными вспомогательными линиями видимости и выключенным округлением. Изменение протяжённости линий не должно блокировать перепривязку; точка вставки, ориентация, размерные параметры и `GH_GUID` должны сохраниться.
8. Повторить для выбранных готовых отверстий/гильз в стенах и плитах, включая WEANDREVIT, с явно выбранным уровнем: сравнить основу, связи соединения/вырезания, положение, размеры и `GH_GUID`. Проверить сохранение выреза визуально в разрезе и 3D. Для уровня только для чтения ожидается новый экземпляр с новым Revit ID; закреплённое отверстие после успешной замены остаётся закреплённым. При ошибке создания старое отверстие должно восстановиться.
9. Для плиты с уровнем основы, отличающимся от уровня отверстия, проверить абсолютную отчётную отметку до/после ручной перепривязки, затем после следующего изменения с включённым автоматическим обновлением RibbonCITRUS.
10. Проверить, что автоматический/проектный режим не перепривязывает готовые отверстия. Повторить ручную замену с включённым округлением: координаты готового отверстия должны остаться прежними. Допустима потеря его марок и размеров на чертежах.
11. Повторно запустить Cutter для задания после смены уровня: неизменённый ранее результат должен распознаться; прежние ручные изменения должны оставаться обнаружимыми. С настроенным Hub проверить переход результата со старого Revit UniqueId на новый. Без настройки Hub не должно появиться задержек сети или предложений подключения.

Эти проверки геометрии в Revit остаются обязательной ручной приёмкой: автоматически запуск на пользовательской модели не выполнялся.
